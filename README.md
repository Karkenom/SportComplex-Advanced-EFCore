# Шаблон практической работы: Введение в Entity Framework Core (Тема: Спорткомплекс)

Учебный проект для знакомства с технологией ORM на примере Entity Framework Core и локальной базы данных SQLite.

Проект показывает, как C#-код управляет данными в базе без прямого написания SQL-запросов: как работают операции добавления, чтения, обновления и удаления, как контекст отслеживает изменения объектов и как устроены связи между таблицами.

## Требования для запуска
* Visual Studio 2026
* Платформа .NET 10.0 или выше
* Установленный через NuGet пакет Microsoft.EntityFrameworkCore.Sqlite

## Как запустить проект:
1. Скопируйте ссылку вашего личного репозитория с GitHub.
2. Откройте Visual Studio.
3. Нажмите на кнопку Клонирование репозитория.
4. Вставьте ссылку.
5. Откройте файл решения (.slnx).
6. Нажмите комбинацию клавиш Ctrl + F5 (запуск без отладки).
7. Программа автоматически создаст файл базы данных sportcomplex_adv.db, заполнит его начальными данными и по очереди выполнит примеры работы с EF Core.

## Структура проекта
* Models - классы данных (сущности): 
  * Membership.cs - типы абонементов спорткомплекса (связь один-ко-многим).
  * Client.cs - клиент (хранит ссылку на абонемент и ключ от шкафчика).
  * LockerKey.cs — электронный ключ от шкафчика (связь один-к-одному с клиентом).
* Data — настройка подключения и данных:
  * SportComplexDbContext.cs — контекст базы данных, регистрация таблиц, настройка связей Fluent API и конвертация типов.
  * DbInitializer.cs — логика сброса и наполнения базы тестовыми записями.
* Demos — практические сценарии работы с Entity Framework:
  * SportCrudOperations.cs — примеры операций Create, Read, Update, Delete.
  * SportChangeTracker.cs — демонстрация состояний объектов.
  * SportRelationships.cs — работа со связанными объектами и каскадное удаление.
* Program.cs — точка входа, главное прога которая всё запускает.

## Как устроена перезапись базы данных
При разработке часто приходится добавлять новые поля в классы (например, телефон или адрес). Чтобы не настраивать сложные миграции и не ловить ошибки несовпадения колонок, в классе DbInitializer прописан вызов context.Database.EnsureDeleted() перед context.Database.EnsureCreated(). 

Это значит, что при каждом запуске старый файл базы данных удаляется и тут же создается заново с актуальными полями и тестовыми данными. Научено из прошлого проекта)

## Инструкция по переделке под свой вариант
Каждому студенту необходимо адаптировать этот проект под свою предметную область (например: автосервис, библиотека, отель, склад, больница):

1. Шаг первый. Папка Models:
Удалите классы студентов и групп. Напишите 3 свои сущности. Настройте между ними внешние ключи и навигационные свойства (минимум одну связь один-ко-многим и одну связь один-к-одному).

2. Шаг второй. Файл Data/SportComplexDbContext.cs:
Замените старые DbSet на ваши новые классы.

3. Шаг третий. Файл Data/DbInitializer.cs:
В методе Initialize удалите старых студентов и напишите создание тестовых объектов под вашу тему, после чего сохраните их через context.SaveChanges().

4. Шаг четвертый. Папка Demos:
Перепишите сценарии под ваши объекты:
* В первом файле покажите добавление записи, поиск по первичному ключу, изменение любого поля и удаление.
* Во втором файле покажите отслеживание состояний вашего объекта через db.Entry().State.
* В третьем файле покажите создание главного объекта вместе с дочерним и проверьте, как работает удаление главной записи (каскадное удаление).

5. Шаг пятый. Проверка:
Запустите проект через Ctrl + F5 и убедитесь, что в консоли по порядку выводятся результаты всех трех блоков без ошибок.
